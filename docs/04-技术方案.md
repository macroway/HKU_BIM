# CheckBIM Agent — 技术方案与实现计划

> 版本：MVP v0.1 · 2026-08-24  
> 依据：[02-PRD.md](02-PRD.md)、[设计说明.md](../design/设计说明.md)、已选 UI `design/ui-option-1.html`  
> 栈选型：**A** Python 单体 + ifcopenshell + 轻量 LLM 工具调用  
> Agent 规划：**P1** 受控 ReAct（白名单工具 + 步数上限 + 强制绑定工具结果）

**本文件只做方案，不包含业务代码实现。**

---

## 1. MVP 要解决的问题，以及本次明确不做的内容

### 要解决

- 交付前：用户上传 IFC 或选样例，用自然语言触发检查。
- 两条规则：**几何碰撞**（墙/梁/管道等）、**属性完整性**（Name / FireRating 等）。
- Agent **自主选工具**（受控 ReAct），但检查结果必须来自本地工具，禁止编造。
- JSON 金标可自动测；小 IFC 可演示；桌面深色 CAD 风格入口（方案 1）。

### 明确不做（Out）

- 疏散门净宽、疏散距离等第二条几何规范。
- 开放式长程规划（P2）、无工具的「假对话 Agent」作为唯一路径。
- 微服务、消息队列、K8s、多租户、写回 IFC、手机端专项优化。
- 完整 3D BIM 编辑器；全量规范库。

## 2. 推荐的技术栈

| 技术 | 解决什么问题 | 为什么适合 |
|------|--------------|------------|
| **Python 3.11+** | 后端与检查引擎统一语言 | ifcopenshell 生态成熟；测试脚本简单 |
| **FastAPI + Uvicorn** | HTTP API：上传、样例、Agent 对话 | 轻量、异步友好、自动 OpenAPI，单体够用 |
| **ifcopenshell** | 解析 IFC、取几何/属性 | 笔试建议路径；对应「真实模型」演示 |
| **自研 JSON 模型适配器** | `test_samples/` 金标路径不依赖 IFC | 快测、可复现、与 PRD 双数据策略一致 |
| **AABB 碰撞（第一版）** | 构件包围盒相交判定 | 实现快；优先降漏报；精确网格碰撞列为以后 |
| **OpenAI 兼容 Chat Completions + tool calling** | 意图与多步工具选择、结果叙述 | 实现 P1 ReAct；可换供应商 |
| **规则路由 fallback** | 无 API Key / 离线 | 保证本地与 CI 可跑通防编造路径 |
| **静态前端（HTML/CSS/JS）** | 按 ui-option-1 改造为调 API | 7 天内不引入重型前端框架 |
| **pytest** | 金标对比与 Agent 护栏测试 | 对应 PRD 验收 |
| **python-dotenv** | 密钥配置 | `.env` + `.gitignore` |

**不引入（第一版）：** LangChain/LlamaIndex（可选以后）、数据库、Redis、Docker Compose 多服务。

**备选（仅真实取舍时）：** 若 ifcopenshell 安装困难，演示可临时「IFC→预提取 JSON」；引擎仍跑同一套碰撞/属性逻辑。

## 3. 程序整体结构与模块责任

```
Test/HKU/app/   （实现阶段创建）
├── main.py                 # FastAPI 入口
├── config.py               # 环境变量
├── api/
│   ├── models.py           # 上传 / 列样例 / 当前模型
│   └── chat.py             # Agent 对话接口
├── agent/
│   ├── loop.py             # P1 ReAct 循环（步数上限）
│   ├── prompts.py          # 系统提示与防编造规则
│   ├── llm_client.py       # OpenAI 兼容客户端
│   └── router_fallback.py  # 无 LLM 时的规则意图路由
├── tools/
│   ├── collision.py        # 碰撞检查
│   ├── attributes.py       # 属性检查
│   └── registry.py         # 工具白名单与 schema
├── models/
│   ├── loader.py           # IFC / JSON 统一载入 → InternalModel
│   ├── schema.py           # 内部构件/包围盒数据结构
│   └── store.py            # 上传文件与会话模型 ID（内存+磁盘）
├── static/                 # 由 ui-option-1 改造的前端
└── tests/                  # pytest
test_samples/               # 金标输入与 expected
uploads/                    # 用户上传（gitignore）
docs/、design/、memory.md
```

| 模块 | 责任 |
|------|------|
| `loader` | IFC/JSON → 统一 `InternalModel`（elements: id, type, name, props, aabb） |
| `tools.*` | 纯函数检查；只读模型；返回固定 JSON schema |
| `agent.loop` | 调 LLM → 执行 tool_calls → 写回 observation → 直到结束或达上限 |
| `api` | 鉴权无；校验文件类型/大小；返回 reply + tool_traces + results |
| `static` | 双入口 UI；展示对话与工具轨迹 |

## 4. 用户流程与数据流

> PRD 场景对应「上传/选模型 → 检查 → 看结果」（非模板中的图片/Excel）。

```
[浏览器] 上传 IFC 或 选择样例
    → POST /api/models/upload | GET /api/models/samples + POST /api/models/select
    → 服务端保存文件，返回 model_id
    → InternalModel 缓存（内存）

[浏览器] 发送自然语言（如「两个都查」）
    → POST /api/chat { model_id, message, history? }
    → agent.loop:
         LLM 规划 tool_calls
         → tools.collision / tools.attributes（读 InternalModel）
         → 结构化结果进入 messages
         → LLM 生成摘要（仅基于工具 JSON）
    → 响应 { reply, tool_traces[], results{collision, attributes}, did_run_tools }

[浏览器] 渲染：对话气泡 + 碰撞表 + 属性表 +（可选）tool_traces 证明真跑过
```

**数据流要点：** 检查结论的唯一事实来源是 `tools.*` 输出；LLM 不得绕过工具写入「通过/无碰撞」。

## 5. 主要数据对象

### InternalElement

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 稳定 ID（IFC GlobalId 或 JSON id） |
| `type` | string | 如 IfcWall / Wall |
| `name` | string \| null | |
| `props` | object | 含 FireRating 等 |
| `aabb` | `{min:[x,y,z], max:[x,y,z]}` \| null | 无几何则跳过碰撞但不漏属性检查 |

### CollisionResult

```json
{
  "pairs": [
    {"a": "id1", "b": "id2", "a_type": "IfcWall", "b_type": "IfcPipeSegment", "a_name": "...", "b_name": "..."}
  ],
  "engine": "aabb_v1",
  "element_types_checked": ["IfcWall", "IfcBeam", "IfcPipeSegment"]
}
```

### AttributeResult

```json
{
  "missing": [
    {"id": "...", "type": "IfcDoor", "field": "FireRating"}
  ],
  "fields_checked": ["Name", "FireRating"],
  "types_checked": ["IfcWall", "IfcBeam", "IfcPipeSegment", "IfcDoor"]
}
```

### 校验与存储

- 上传：扩展名 `.ifc` / `.ifczip`；大小上限建议 50MB；病毒扫描不做（MVP）。
- 样例：只读 `test_samples/` 与 `test_samples/demo/`。
- 上传文件：`uploads/{model_id}.ifc`；进程重启可丢内存缓存，可按需重载。
- 删除：提供 `DELETE /api/models/{id}`（可选 MVP）；演示结束可手动清 `uploads/`。
- 金标：`*.expected.json` 与结果比对前对 `pairs` / `missing` **按 id 排序规范化**。

## 6. 前端与后端配合；外部服务接入

| 端 | 行为 |
|----|------|
| 前端 | 静态资源由 FastAPI `StaticFiles` 挂载；`fetch` 调 API；按钮真实可用（实现阶段） |
| 后端 | 全部业务逻辑；密钥只在后端读 |
| LLM | HTTPS 调用 OpenAI 兼容端点；`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` |
| ifcopenshell | 本地库，无云端 BIM 服务 |

**工具注册（白名单示例）：**

- `run_collision_check(model_id)`
- `run_attribute_check(model_id)`
- `get_model_info(model_id)`（构件数、类型统计，辅助叙述）

LLM 不得获得「任意代码执行」或「写文件」类工具。

## 7. 异常与边界处理

| 情况 | 处理 |
|------|------|
| 等待 LLM | 前端显示「正在规划/检查…」；后端超时（如 60s）返回错误 |
| LLM 失败 | 自动降级 `router_fallback`；或返回明确错误，**不**生成假检查结论 |
| 工具失败 | `tool_traces` 记 error；回复说明失败；禁止「检查通过」 |
| 未选模型就对话 | 400：请先上传或选择样例 |
| 重复上传 | 新 `model_id`；旧文件可保留或覆盖策略写进配置 |
| 损坏/非 IFC | 载入失败，明确报错 |
| 无几何 AABB | 该构件不参与碰撞；属性仍检查；在结果 `warnings` 中说明 |
| 「两个都查」 | ReAct 连续调两个工具；步数计入上限 |
| 重复同一检查 | 允许；可用短缓存（可选，非必须） |
| 客户改模再传 | 新上传新 id；会话需带新 model_id |

**防编造硬规则（代码级）：** 若本轮 `did_run_tools` 为 false 且用户在问检查结果，则覆盖 LLM 输出为「尚未执行检查，请先让我调用检查工具」类提示（或强制再跑 fallback 工具）。

## 8. 性能、可扩展性、安全、可观测性

| 维度 | 第一版必须做 | 以后再做 |
|------|--------------|----------|
| 性能 | JSON &lt; 30s；演示 IFC 小文件；AABB O(n²) 可接受（n 小） | BVH、并行、精确几何 |
| 扩展 | 新规则 = 新 tool + registry | 插件市场、多租户 |
| 安全 | `.env`、gitignore、密钥不进前端、上传类型/大小限制 | 鉴权、沙箱 |
| 数据 | 本地 uploads；日志不打印完整模型 | 对象存储 |
| 可观测 | `tool_traces` 返回前端；可选写 `data/logs/runs/` | OpenTelemetry |

## 12. 风险、取舍、暂定假设、仍需决定

### 暂定假设（可验证）

1. 碰撞类型：`IfcWall`、`IfcBeam`、`IfcPipeSegment`（及 JSON 中等价 type 名）。  
2. 属性：上述类型 + `IfcDoor`；字段 `Name`、`FireRating`；空字符串视为缺失。  
3. 碰撞算法：AABB 相交即报；不设间隙容差（优先防漏报；误报可接受）。  
4. ReAct 最大步数：**5**；每步只允许白名单 tool。  
5. 无 Key：`router_fallback` 关键词映射到固定工具序列。

### 风险与取舍

| 风险 | 取舍 |
|------|------|
| AABB 误报 | 接受；文档说明；精确碰撞以后做 |
| ifcopenshell 安装失败 | 预提取 JSON 演示兜底 |
| LLM 不稳定 | 护栏 + fallback；演示可走离线 |
| O(n²) 慢 | 限制演示模型规模 |

### 仍需决定（不阻塞开工）

- 具体 LLM 供应商与模型名  
- 演示 IFC 精确文件来源  
- 是否在 UI 默认展开 tool_traces

## 附录：P1 Agent 规划要点

1. 系统提示：检查结论必须来自工具；禁止无工具宣称通过。  
2. 循环：`while steps < 5 and not done`：LLM → tool_calls → execute → append observation。  
3. `done`：LLM 不再请求工具，或已拿到用户所需工具结果并给出最终回复。  
4. 对外可解释：响应带 `tool_traces`，体现「自主选工具」而非固定死脚本（fallback 模式可标注 `planner: rules`）。
