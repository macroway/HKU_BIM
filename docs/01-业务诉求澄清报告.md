## 1. 业务一句话

在 7 天内交付一个**对话驱动的智能 Agent**，能对建筑模型执行**几何碰撞检测**与**关键属性完整性检查**，并以可复现的测试数据和可视化结果，满足 HKU AI Agent 岗位笔试提交要求。

---

## 2. 核心问题与目标

### 要解决的问题

建筑/BIM 模型在交付前常存在两类基础问题：

1. **几何冲突**：墙、梁、管道等构件在空间上发生碰撞，施工前难以发现。
2. **属性缺失**：构件缺少 Name、FireRating 等关键属性，影响合规审查与算量。

应试者需在有限时间内证明：**能用 Agent 工程化方式**，把上述检查自动化，并给出清晰、可演示的结果。

### 目标

| 目标 | 说明 |
|------|------|
| 可运行 | Agent 能接收模型、执行检查、返回结构化结果 |
| 有思考 | 规则选择、数据策略、技术取舍有文档与代码体现 |
| 有品味 | 交互自然、结果可视化有帮助、代码结构清晰 |
| 可提交 | GitHub（代码+提示词）+ 3 分钟演示视频 + 简历 |

## 3. 关键角色

| 角色 | 诉求 |
|------|------|
| **应试开发者** | 7 天内完成 MVP，展示 Agent 工程化与学习速度 |
| **HKU 评审** | 验证潜力与判断力，非建筑领域深度 |
| **演示中的「用户」** | 通过自然语言驱动检查，上传/指定 IFC 模型，读懂碰撞与属性报告 |
| **自动化测试** | 通过 JSON 样例与标准答案验证回归，不依赖人工每次点选 |

## 4. 主流程

```
用户打开 Agent 界面
    ↓
用自然语言发起意图（如「检查碰撞」「查防火属性」）
    ↓
上传或指定 IFC 模型（演示路径）/ 使用内置 JSON 样例（测试路径）
    ↓
Agent 解析意图 → 调用对应检查 Skill
    ↓
规则 1：几何碰撞 → 输出冲突列表 + 可视化（位置/构件对）
规则 2：属性检查 → 输出缺失 Name / FireRating 的构件清单
    ↓
Agent 用对话解释结果，供用户理解 severity 与下一步
    ↓
（笔试）录制 3 分钟演示 → 提交 GitHub + 视频 + 简历
```

---

## 5. 需求优先级

### Must（第一版必须）

- 智能 Agent 形态：自然语言理解检查意图，编排至少 2 条规则
- **规则 1**：几何碰撞（墙/梁/管道等）
- **规则 2**：属性完整性（Name、FireRating 等关键字段缺失检测）
- 双数据策略：**JSON** 用于 `test_samples/` 自动化验收；**IFC** 用于演示视频
- 可运行端到端：从输入模型到结构化结果 + 基本可视化
- GitHub 仓库含代码与提示词
- 3 分钟以内演示/介绍视频

### Should（有时间则加强）

- 碰撞结果 3D/2D 高亮或示意图
- Agent 多轮对话：追问某条碰撞详情、筛选严重等级
- README 说明规则依据、局限与扩展方向
- `.env.example` 与密钥安全说明

### Out（本次明确不做）

- 疏散门净宽度、房间到出口距离等**第二条几何规范**（复杂度高，与 7 天排期冲突）
- 完整 BIM 规范库或全量合规引擎
- CAD 原生格式深度支持（优先 IFC + JSON）
- 微服务、分布式部署、多租户权限
- 追求建筑领域专业深度或规范条文全覆盖

## 6. 约束与风险

| 类型 | 内容 |
|------|------|
| **时间** | 7 天硬截止 |
| **范围** | 仅 2 条规则；精炼优先 |
| **技术自由** | Python+ifcopenshell、JS、LangChain 等均可，需自洽 |
| **评审侧重** | 学习速度、工程判断力、潜力 > 建筑专业知识 |

### 主要风险

1. **IFC 解析与碰撞性能**：大模型文件可能导致演示卡顿 → 演示用精选小体积 IFC，测试用 JSON。
2. **Agent scope 膨胀**：对话式易无限扩展 → PRD 阶段锁定意图集与工具列表。
3. **属性规则边界**：FireRating 适用构件类型需定义清楚 → 技术方案中列明检查对象与字段 schema。
4. **双数据一致性**：JSON 与 IFC 检查结果需语义对齐 → 测试样例与标准答案要成对设计。
