## 录制前准备（录之前完成，不出镜）

```bash
cd Test/HKU
cp .env.example .env   # 若尚未配置
# .env 关键项：

# LLM_PROVIDER=ark
# ARK_API_KEY=你的密钥

# 期望：available=true, provider=ark, planner_label=doubao
```

| 项 | 要求 |
|----|------|
| 浏览器 | 全屏，宽度 ≥1280；缩放 100% |

| 网络 | 可访问火山方舟 API |

## 第一幕 · 产品定位（0:00–0:25）

**镜头**：从标题栏缓慢扫到左（入口）→ 中（视口）→ 右（Agent）。

**口播（拍摄参考，终稿见录屏后生成）**：

> 这是 CheckBIM Agent：给 BIM 工程师做**交付前自查**——几何碰撞和属性完整性，用对话驱动，不用填表单。  
> 右侧由**豆包 Doubao**做意图理解和工具规划；中间的碰撞和属性**计算在本地引擎**，结论必须来自工具调用。

**停留 2 秒**：指一下右上角 **`Doubao · …`** 和 **`规划器 · Doubao · 待命`**。

---

## 第二幕 · 载入 IFC + 综合自查（0:25–1:20）【核心】

### 2.1 载入模型（0:25–0:40）

1. 左侧内置样例 → **`building-l1.ifc`** → 点 **载入**
2. 等中间视口出现平面俯视图（墙/梁/管/门分色）
3. 标题栏变为已载入模型名；构件总数 **10**

**口播（拍摄参考，终稿见录屏后生成）**：

> 先载入一层简化 IFC，十来个构件，命名接近真实项目——墙、梁、风管、防火门。

### 2.2 触发综合检查（0:40–1:20）

1. 点快捷指令 **「交付前过一遍」**（或输入：`交付前帮我过一遍`）
2. **镜头切右侧**：Agent 执行轨迹依次出现  
   `理解意图` → `执行 · 几何碰撞检测` → `执行 · 属性完整性检查`
3. 轨迹跑完后，看对话气泡里的摘要 + 工具标签
4. **镜头切中间**：
   - 统计卡：**碰撞对 4**、**缺失属性 3**
   - 碰撞清单列出构件对（如梁×隔墙、风管×隔墙…）
   - 属性缺失：**FireRating** ×3
   - **点击一条碰撞**，视口对应区域高亮

**口播（拍摄参考，终稿见录屏后生成）**：

> 我说「交付前过一遍」，Doubao 会规划调用两个白名单工具——先碰撞、再属性。  
> 这个模型里预期 **4 对硬碰、3 条防火等级缺失**；摘要里的构件名和数字，都来自工具 JSON，不是模型瞎编。  
> 中间是 2D 平面视口，点清单可以在图上看冲突位置。

**核对**（录完自查）：摘要是否提到 **4** 与 **3**；轨迹是否 **2 个工具**；`规划器 · Doubao · 已调用 2 个工具`。

## 第三幕 · 自然语言分诊（1:20–2:00）

> 体现「不只认关键词」——同一模型，口语化问法，Doubao 选不同工具。

### 3.1 只查碰撞（0:15）

- 输入：**有没有硬碰**（或点同名快捷指令）
- 轨迹应 mainly **几何碰撞检测** 一项
- 口播：*「口语问硬碰，只跑碰撞，不会多余跑属性。」*（拍摄参考）

### 3.2 只查属性（0:15）

- 输入：**防火等级齐全吗**
- 轨迹应 **属性完整性检查**
- 口播：*「问 FireRating，Doubao 只调属性工具，缺失还是那 3 条。」*（拍摄参考）

### 3.3 模型概况（0:10，时间紧可删）

- 输入：**统计一下模型情况**（或点 **统计构件**）
- 轨迹 **读取模型概况**；回复含构件总数
- 口播：*「读模型信息也是工具，不是 LLM 猜的。」*（拍摄参考）

---

## 第四幕 · 护栏与可信度（2:00–2:25）

1. 输入：**`111`**
2. 预期：**不**出现工具轨迹；`规划器 · Doubao · 未执行工具`；回复为澄清意图（请说明查碰撞/属性）
3. 对话区**不应**出现「检查通过」「无碰撞」等结论

**口播（拍摄参考，终稿见录屏后生成）**：

> 无意义输入会被拦住，不会假装跑完检查。  
> 就算 Doubao 在规划，**碰撞和属性算法仍是本地确定性引擎**——LLM 只负责听懂人话、选工具、写摘要。

---

## 第五幕 · 收尾（2:25–3:00）

**镜头**：可回到三栏全景或 GitHub 仓库页（二选一）。

**口播（拍摄参考，终稿见录屏后生成）**：

> 整体是受控 ReAct：最多五步、三个白名单工具；没跑工具就不能下检查结论。  
> 代码、提示词和产研文档在 GitHub；JSON 金标 + 这层 IFC 样例，测试和演示走同一套引擎。

**可选一句**（若还有时间）：上传区支持 **IFC / JSON**，工程师可以换自己的模型文件。
